### Context
Slice S7 exposes UMA to any MCP client (Claude Code, Cursor, OpenCode, Codex). MCP has **no approval modal**, unlike the Pi extension, so the existing approval gate cannot protect this new tool path.

### Decision
`uma mcp serve` is **read-only by default**: it advertises and permits `uma_read`, `uma_list`, `uma_search`, `uma_consolidate`. `uma mcp serve --allow-writes` additionally enables `uma_write` and `uma_supersede`. The operator's launch flag **is** the consent step.

Mutations are refused **server-side** when the flag is absent — not merely omitted from `tools/list` — so a client cannot reach a write by guessing a tool name. `is_mutating()` reads the same `mutating` flag that `tools/list` advertises, so the catalogue and the enforcement rule cannot drift apart.

### Consequences
- **Approval belongs to the tool path.** Pi obtains consent per-write via the modal; MCP obtains it once at launch; the CLI's consent is the human typing the command.
- Restarting with the flag is the only way to enable writes — there is no in-band escalation.
- A read-only client can never modify memory, even via malformed or hostile arguments.
- Implementing S7 as a slice (`uma-cli/src/slices/mcp/`) rather than a separate `uma-mcp/` crate keeps the VSA mandate: a separate crate would be a horizontal layer.
