### Context
As the codebase grows across progressive slices (S0 to S9), inter-module dependencies can lead to spaghetti code and circular dependencies.

### Pattern / Rule
- Feature slices in `src/slices/<feature>.rs` or `src/slices/<feature>/` must NEVER import each other directly (`use crate::slices::other_slice::*` is forbidden).
- All shared types, storage interfaces, serialization logic, and domain entities reside in `uma-core` or `src/shared/`.
- `src/main.rs` is the only place where slices are composed and dispatched.

### Consequences
- Slices can be added, tested, refactored, or removed in total isolation.
- Refactoring one command never breaks other commands.
